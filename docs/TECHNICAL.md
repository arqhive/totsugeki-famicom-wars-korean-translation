# 기술 문서

일본판 `G8WJ01`(Kuju Entertainment 엔진) 기준입니다. 디스크 안 파일은 압축되어 있지 않습니다.

## 디스크

- 표준 GC 디스크입니다. 파일 3,576개 중 음성(`.adp`) 2,955개는 32KB 경계에 놓여 있습니다.
- 파일 영역은 가득 차 보이지만 FST 뒤에 약 338MB가 비어 있습니다.
- `build_iso.py`는 바뀌지 않은 파일을 원래 위치에 그대로 두고, 바뀐 파일은 원래 자리에 들어가면 제자리, 커졌으면 앞쪽 빈 영역에 둡니다. 음성 파일의 정렬과 읽기 위치가 그대로 유지됩니다.

## 문자열 `Data/Strings/*.str`

리틀 엔디언입니다.

| 위치 | 내용 |
|---|---|
| 0x00 | magic `0x0005A177` |
| 0x04 | 항목 수 |
| 0x08 | 파일 전체 크기 |
| 0x10부터 | 항목 0x38바이트씩 |

항목은 색(`0x007F7F7F`), 음성 폴더·음성 ID·예비 문자열(ASCII) 오프셋, 표시 시간(float, +0x14), 본문 오프셋(+0x1C)을 담습니다.
본문은 u16 배열이고 0으로 끝나며 4바이트로 정렬됩니다. `loading_screen_*`·`star*`는 칸마다 여유 바이트(0xCD)가 있어, `strfile.py`는 원래 칸을 보존해 다시 씁니다.
331개 파일 모두 읽고 다시 써도 원본과 바이트 단위로 같습니다.

- 영어 등은 UTF-16 코드입니다.
- 일본어는 문자 코드가 아니라 **글자 번호**입니다. 상위 바이트 `0xB0`+시트, 하위 바이트 `0x40`+칸(0에서 120까지)이고, 줄바꿈은 `0x0A`입니다.
- 영문 포함 폰트에서 상위 바이트가 0이면 ASCII 칸(코드−0x20)을 씁니다.
- 일본판 디스크에는 6개 언어 파일이 모두 들어 있습니다. 게임은 `*Japanese.str`과 `globjap.str`을 읽습니다.

## 폰트 `Data/font/<장면>.btf` + `.wdf`

- `.btf`: `FTBX` 헤더와 `TXET` 청크(256×256, C4, RGB5A3 16색 팔레트) 여러 장입니다. 청크 크기 필드는 청크 헤더 8바이트를 뺀 값입니다.
- 칸은 22×22 격자이고 시트당 11×11=121칸입니다. 칸 위치는 고정입니다(실행 코드 `0x801D11AC`가 `(상위+0x50)*121+(하위−0x40)`로 칸을 구함).
- `.wdf`: 칸마다 글자 폭 1바이트입니다. 길이가 곧 폰트의 글자 수입니다.
- 장면마다 그 장면에 쓰인 글자만 모은 폰트를 씁니다. 미션·메뉴 폰트는 칸 0에서 95까지 ASCII, 그다음 공통 문자열(`globjap.str`) 글자, 그 뒤 장면 글자 순서입니다. 스토리 폰트는 장면 글자만 있습니다.
- 시트 수에는 사실상 한계가 없습니다. 원본 최대 8장보다 많은 10장짜리 폰트도 정상 출력되는 것을 확인했습니다.

한글 폰트(`korglyph.py`)는 G마켓 산스 Medium 17px을 4배 해상도로 그려 원본 모양을 흉내 냅니다.
흰 채움, 둥근 1px 검은 테두리, 아래로 2px 내린 그림자를 합성한 뒤 원본 16색 팔레트로 줄입니다.
글자 간격은 18px로, 일본어 한자·가나와 같습니다. 기호·영숫자(스토리 폰트)와 괄호(「」『』)·♪는 잉크 폭+1px 간격입니다. 말줄임표·줄표만 18px입니다.

## 원문 판독

일본어 원문이 글자 번호뿐이라 폰트 그림을 읽어 복원합니다.

- `collect_shapes.py`가 모든 폰트 칸의 밝기를 잘라 md5로 모양을 식별합니다(고유 2,782개).
- 같은 글자 모양을 묶은 1,646개 묶음(`tools/data/review.json`)을 사람이 검수 시트로 판독했습니다(`tools/data/labels/*.txt`).
- 모양이 비슷한 글자(説·脱, 達·連, 関·開, 特·持, 闇·聞 등)가 한 묶음에 섞인 19개 모양은 `fix_shape.json`에 따로 적었습니다.
- 모양이 같은 가타카나와 한자·히라가나(ロ·口, エ·工, カ·力, ハ·八, オ·才, ヘ·へ 등)는 앞뒤 글자로 정합니다.
- 칸 95는 폭 6px의 좁은 공백입니다.

## 텍스처 `TXET`

리소스(`*_Level.res`)와 `.btf` 안에 들어 있습니다. 형식은 DXT1(CMPR), P8(C8), P4(C4), A8R8(RGBA8)이고, 팔레트는 ` LAP`, 픽셀은 ` PIM` 하위 청크입니다.
고유 텍스처 1,187종을 전수 확인했고, 일본어가 들어간 것은 아래 셋입니다. 텍스처가 아닌 디스크 배너 그림은 다음 절에 있습니다.

| 텍스처 | 위치 | 형식 |
|---|---|---|
| `BWTitleLogoJp` 592×168 | `Data/CompoundFiles/frontend_0_Level.res` | P8, 256색 |
| `warningJap` 608×448 | `Data/Startup/WarningJap.btf` | DXT1 |
| `pstartJap` 608×48 | `Data/Startup/WarningJap.btf` | DXT1 |

`texenc.py`가 같은 크기로 인코딩해 제자리에 덮어쓰고, 다시 풀어 원본 PNG와 비교합니다.

## 디스크 배너·메모리카드

엔진 텍스처(`TXET`)가 아니라서 따로 다룹니다.

| 대상 | 위치 | 내용 | 처리 |
|---|---|---|---|
| 배너 그림 96×32 | `opening.bnr` 0x20부터 0x1800바이트 | RGB5A3(4×4 타일), 일본어 로고 | `tools/assets/banner.png`가 있으면 `texenc.encode_rgb5a3`로 교체. 원본을 풀었다 다시 넣으면 픽셀이 모두 같음. |
| 배너 문구 | `opening.bnr` 0x1820부터 | 짧은·긴 제목, 제작사, 설명(Shift-JIS) | 한글을 넣을 수 없어 그대로 둠. |
| 세이브 이름·설명 | `main.dol` 0x2AE476 | 「突撃！！ファミコンウォーズ」, 「セーブデータ」(Shift-JIS) | 그대로 둠. |
| 세이브 아이콘 | `MemCard/iconc.tpl` | 32×32 C8 8장, 별 그림 | 글자 없음. |
| 디스크 오류 메시지 | `main.dol` 0x2C6788 | 본체 ROM 폰트로 그리는 Shift-JIS 문구 | 그대로 둠. |

## 쓰지 않는 파일

- `Data/Strings/1.1_*`처럼 점이 든 이름의 자막 파일 7개(일본어 38항목)는 짝이 되는 폰트가 없고, 무비 목록(`frontend_1_Level.res`)에는 밑줄 이름 12개만 있어 쓰이지 않습니다.
- `loading_screen`, `fmvsubtitles` 폰트는 원본 일본어 공통 문구조차 엉뚱한 글자로 찍혀(「次へ」가 「ブお」), 일본판에서 쓰지 않는 옛 폰트입니다.

## 무비

스토리 무비(`Data/Video/*.h4m`, HVQM4)의 자막은 영상과 별개로 게임이 문자열 파일(`1_1_NewsDrill_Japanese.str` 등)과 전용 폰트로 그립니다.
데모 영상(`AttractMode_jp.h4m`)은 일본어 자막 문자열이 비어 있고 폰트도 비어 있어 번역할 자막이 없습니다.

### 오프닝 로고 무비 `BW_Title_JP.h4m`

640×480, 30fps, 97장(3.2초)이고 소리는 따로 있는 `BW_Title_JP_L/R.adp`입니다. 영상에 일본어 로고가 그려져 있어 새로 만들었습니다.

- 파일 구조: 헤더 0x44바이트(장 수, 묶음 수, 장 길이 33,333µs, 가장 큰 장 크기) 뒤에 30장씩 묶음(GOP)이 이어집니다. 묶음 머리는 이전 묶음 길이, 본문 길이, 영상·소리 장 수, `0x01000000`입니다. 장마다 종류(I 0x10, P 0x20, B 0x30), 길이, 표시 번호가 붙습니다.
- 인코더(`tools/h4m.py`): 공개된 HVQM4 인코더가 없어 직접 만들었습니다. 모든 장을 I 프레임으로 넣고, 4×4 블록을 단색 블록(종류 8, DC 값만)이나 원본 픽셀 블록(종류 6, 16바이트 그대로) 둘로만 씁니다. 블록 종류·DC 차이값은 장마다 만든 허프만 표로, 연속된 0은 run 길이로 적습니다. Tilka/hvqm4 디코더로 다시 풀어 원본 97장이 픽셀까지 같게 나오는 것을 확인했습니다. 원본(0.8MB)보다 커서 8.6MB가 되며, Dolphin과 Wii U vWii + Nintendont에서 정상 재생을 확인했습니다.
- 연출 재현(`tools/movie`): 로고를 노란 글자 속 기준으로 「돌격!!」·「패미컴」·「워즈★」 세 조각으로 나눕니다. 원본 영상에서 「突撃!!」은 장마다 배율·위치를 색 비교로 찾았고, 미끄러져 들어오는 「ファミコン」·「ウォーズ★」는 노란 글자 끝 위치로 이동·가로 눌림을 쟀습니다(`data/track2.json`, `gen.py`의 표). 번쩍임은 로고를 크림색으로 섞고 흐리게 하는 세기를 장마다 원본에 맞췄습니다(`data/flash2.json`). 파편 줄과 마지막 빛 줄기는 원본 장면에서 옮겨 옵니다.
- 마지막 장은 게임 타이틀 로고 텍스처를 원본 영상과 같은 위치(34, 72)에 1:1로 놓아, 영상이 끝나고 타이틀 화면으로 넘어갈 때 로고가 튀지 않게 했습니다. 확대 장면은 같은 로고의 고해상도판(`tools/assets/movie/BWTitleLogo_hires.png`)을 씁니다.

### 엔딩 로고 무비 `4_3_TheEnd_JP.h4m`

마지막 컷씬(2,452장) 끝 2171~2307장에 일본어 로고가 나옵니다. 로고가 든 묶음 73~77번(2163~2312장)만 I 프레임으로 새로 만들고 나머지 묶음은 원본 바이트를 그대로 둡니다(`tools/movie/make_ending.py`, 18.2MB → 29.4MB).

- 나타나기(2171~2294장): 정지 장면(2260장)을 기준으로 장마다 배율(1.22→1)과 밝기(0→1)를 원본에서 쟀습니다(`data/ending_track.json`). 한글 로고는 타이틀 로고 텍스처(™ 뺌)를 원본 로고 자리에 맞춰 놓습니다.
- 흰색 전환(2295~2307장): 노란 면을 흰색으로, 다시 흰 실루엣과 가로 흐림·빛 번짐으로 바꾸는 값을 눈으로 맞췄습니다.
- 흰 띠(2308장~)는 글자가 없어 원본 장면 그대로입니다.
